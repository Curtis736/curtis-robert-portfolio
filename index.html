Ce que j'ai fait, en détail


    

      SEDI-ATIsept. 2025 → aujourd'hui · Ingénieur DevOps
      
Fabricant de fibres optiques. Je gère l'infra on-premise de FSOP, l'application de traçabilité de la production : les opérateurs pointent sur des tablettes, les données passent par une API et SQL Server, puis partent chaque jour vers l'ERP SILOG. Le parc mélange Linux (Red Hat, Ubuntu) et Windows.


      
L'application en production

      
    
        
  • Mise en service de FSOP sur fsop.sedi-ati.com : pointage des temps sur les lancements de production (démarrer, mettre en pause, terminer une étape), temps restant estimé par lancement, fiches de traçabilité (composants, lots, mesures) et écran admin pour superviser les opérateurs.
    • 
        
  • Architecture : interface tablette en JavaScript servie par Nginx (HTTPS), API Node.js / Express 5 avec JWT, SQL Server (base applicative + base ERP), Redis en cache, et montages réseau CIFS vers les dossiers qualité.
    • 
        
  • Plusieurs machines, chacune son rôle : prod, test, CI et le serveur Windows de l'ERP, pour qu'une version cassée ou un build lourd ne ralentisse jamais l'atelier.
    • 
      


      
Infrastructure en code

      
    
        
  • Terraform déclare les hôtes (prod, test, CI, ERP) et génère l'inventaire Ansible : une seule source de vérité.
    • 
        
  • Ansible pour Linux et Windows : j'ai écrit le rôle silog_ssh_runner qui prépare le serveur Windows de l'ERP (OpenSSH, configuration sshd, pare-feu, clé, tâche planifiée de secours), d'abord via WinRM puis en SSH, avec les collections ansible.windows / community.windows. Des playbooks de vérification en lecture seule contrôlent l'état sans rien modifier.
    • 
        
  • Une cinquantaine de machines pour les applications internes, provisionnées dans des états préconfigurés, sécurité comprise.
    • 
        
  • Secrets dans HashiCorp Vault, images Docker non-root, service systemd pour relancer l'appli au démarrage.
    • 
      


      
Chaîne de livraison

      
    
        
  • GitHub Actions répliqué vers GitLab CI, plus Jenkins, en trois pipelines : intégration complète, tests rapides et sécurité.
    • 
        
  • À chaque push : tests backend sur plusieurs versions de Node avec couverture, smoke test du frontend, contrôle qualité, npm audit (niveau high), tests d'exécution (health check), validation des builds Docker, analyse SonarQube.
    • 
        
  • Prod verrouillée : le déploiement ne part que par un runner GitLab dédié. Images construites une fois, Compose séparés pour la prod, le test, le dev et la supervision.
    • 
      


      
Supervision et alertes

      
    
        
  • Prometheus + Alertmanager + Grafana provisionnés en code, avec un dashboard SEDI dédié.
    • 
        
  • 8 alertes : backend injoignable, cible de monitoring tombée, taux d'erreurs HTTP élevé, latence p95 élevée, disque presque plein, RAM saturée, CPU élevé, Redis injoignable.
    • 
        
  • Alertes envoyées sur Teams et par e-mail.
    • 
      


      
Exploitation au quotidien (tout automatisé)

      
    
        
  • Watchdog toutes les 10 minutes qui vérifie la base, les modèles de fiches et la chaîne vers SILOG.
    • 
        
  • Présence des modèles FSOP vérifiée toutes les 5 minutes, intégrité des données toutes les 6 heures, nettoyage des données incohérentes chaque nuit, rapport de santé chaque lundi, purge des logs de plus de 30 jours.
    • 
        
  • Sauvegardes scriptées des volumes Docker, de la config et des certificats, avec rétention de 14 jours.
    • 
        
  • Transfert vers l'ERP : script PowerShell sur le serveur Windows (log horodaté, rotation à 10 Mo, état final Succès / Erreur / Refusé et code de sortie lisible par le planificateur), lancé chaque matin à 7 h.
    • 
        
  • Runbook d'incident écrit, documentation utilisateur pour l'atelier et documentation technique servies directement par l'appli.
    • 
      


      
Outils pour l'équipe qualité

      
    
        
  • AUTO-RCI (Python, Tkinter) : génère automatiquement les fiches Word RCI, RE et PV pour chaque numéro de série à partir des mesures Excel, insère images et courbes, récupère les graphiques dichroïques, remplit la mesure de fin du cyclage thermique et convertit le tout en PDF.
    • 
        
  • Vérificateur de PDF : contrôle en masse que chaque rapport de test porte le bon numéro de série, le bon programme et aucun échec, avec un rapport exportable.
    • 
        
  • Agent de synchronisation FSOP → Excel (service Windows) : dès qu'un opérateur ferme une fiche Word, l'agent lit les valeurs saisies et les écrit dans le classeur de mesures du bon numéro de série.
    •
